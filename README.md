# noti. — 기관 모니터링 업무공간

기관 공지와 웹페이지 변경을 확인하고 업체·프로젝트의 대응 상태를 관리하는 한국어 업무용 사이트입니다.

- GitHub: https://github.com/garajilpung/noti
- Vercel 보호된 미리보기: https://noti-p7zopt10k-garajilpungs-projects.vercel.app
- Next.js 16.4.2 · React 19.3.1 · TypeScript · Neon PostgreSQL
- Vercel 프로젝트: garajilpungs-projects/noti, 함수 및 데이터베이스 지역: Singapore

## 구현 기능

- 월간 캘린더: 날짜별 점검 예정·실행 기록·실패 표시, 한국 시간 기준
- 대시보드: 신규·변경·미확인·검토 필요 집계, 전체/기관별 수동 점검
- 기관: 등록·설정·활성화, 목록 및 본문 선택자, 반복 요소 제외, 최근 성공 시각
- 공지: 기준 자료/신규/본문 변경 분리, 이전·현재 본문 비교, 검색·기간·기관·상태 필터
- 업무: 확인 여부와 대응 상태 별도 저장, 메모·직접 연결·변경 이력, 동시 수정 충돌 방지
- 업체·프로젝트: 다중 기관 연결 및 기관별 관련 공지·이력 조회
- 예정 일정: 캘린더 등록·삭제, 당일 성공 점검 시 완료 처리

## 자료와 실제 연동

기관 목록은 제공받은 원본 자료를 [data/기관_사이트_및_공지사항_URL.md](data/기관_사이트_및_공지사항_URL.md)에 보관했습니다. 기관명과 URL을 임의로 생성하지 않았습니다.

| 실제 수집 기관 | 최초 기준 자료 |
| --- | ---: |
| 공무원연금 | 10건 |
| 국민건강보험 | 12건 |
| 한국도로교통공단 | 12건 |

Vercel 서버에서는 공무원연금·국민건강보험의 재수집이 성공했습니다. 한국도로교통공단은 Vercel에서 응답 시간 초과가 확인되어 실패 이유와 수동 확인 링크를 표시합니다.

총 24개 기관을 등록하고 3곳을 활성화했습니다. 나머지는 연동 준비 상태입니다. 경찰청·eFine은 조사 당시 자동 요청에서 307 리다이렉트가 반복됐으며 수동 확인 안내를 표시합니다.

최초 수집은 기준 자료로 저장하고 신규 알림에 포함하지 않습니다. 기준 자료도 사용자가 미확인 또는 대응 상태를 지정하면 업무 알림으로 조회할 수 있습니다. 실패 이력은 삭제하지 않고 이후 성공 이력과 함께 캘린더에 보관합니다.

## 로컬 실행

Node.js 24와 npm이 필요합니다.

1. 저장소를 받은 뒤 의존성을 설치합니다: `npm ci`
2. 권한이 있는 Vercel 계정으로 로그인합니다: `npx vercel login`
3. 프로젝트를 연결합니다: `npx vercel link --project noti --scope garajilpungs-projects`
4. 환경변수를 받습니다: `npx vercel env pull .env.local --yes`
5. 처음 사용하는 데이터베이스라면 `npm run db:migrate`, `npm run db:seed`를 실행합니다.
6. `npm run dev` 실행 후 http://127.0.0.1:3000 에 접속합니다.

별도 데이터베이스를 사용하는 경우 .env.example을 참고해 DATABASE_URL과 DATABASE_URL_UNPOOLED를 설정하세요. 환경변수 파일과 데이터베이스 내용은 Git에 포함하지 않습니다.

## 검증·수집 명령

| 명령 | 용도 |
| --- | --- |
| `npm run typecheck` | TypeScript 검사 |
| `npm run build` | 배포 빌드 |
| `npm test` | 본문 비교 및 별도 검증 업무공간의 데이터베이스 통합 테스트 |
| `npm run collect` | 활성 기관을 순서대로 수동 점검 |

통합 테스트는 고유한 검증 업무공간을 생성하고 종료 시 해당 자료만 정리합니다. 실제 업무공간의 공지를 예시 데이터로 대체하지 않습니다. 브라우저 확인 결과와 실제 기관 확인 범위는 [검증 기록](docs/verification.md)에 정리합니다.

## Vercel 배포

Vercel 프로젝트에 Neon 무료 데이터베이스를 연결했습니다. 데이터는 함수 파일시스템이나 브라우저 저장소 대신 PostgreSQL에 저장합니다.

`npx vercel deploy --target preview --scope garajilpungs-projects`로 보호된 미리보기 배포를 생성할 수 있습니다. 미리보기에서는 Vercel Authentication을 유지합니다.

첫 버전에는 자체 로그인·사용자별 권한을 구현하지 않았습니다. 공개 운영 배포는 업무 데이터를 노출하지 않도록 현재 503 안내를 반환합니다. 운영 배포를 사용하려면 접근 보호 방식과 로그인 범위를 먼저 결정하고 해당 제한을 교체해야 합니다.

정기 점검은 활성화하지 않았습니다. 캘린더 일정은 자동 실행 예약이 아닙니다. 추후 Vercel Cron 또는 별도 실행 환경에서 scripts/collect.ts와 동일한 서비스 함수를 호출하도록 확장할 수 있습니다.

## 현재 제약

- 목록 첫 페이지 최대 12건만 점검합니다. 이전 페이지로 밀려난 공지의 재수정은 감지하지 않습니다.
- 선택한 본문의 텍스트·이미지 참조를 비교합니다. 첨부파일 내부, 외부 이미지의 동일 URL 내 파일 교체, OCR은 제외합니다.
- 로그인·보안 인증·자바스크립트 실행이 필요한 사이트는 전용 연동이 필요합니다.
- 기관별 수집은 전체 성공 시에만 기준을 갱신합니다. 상세 한 건이라도 실패하면 해당 기관 점검은 실패로 기록합니다.
- 화면은 최근 변경 기록 1,000건, 최근 1년의 점검 이력 최대 2,000건을 조회합니다. 목록 표에는 필터 결과 중 300건까지 표시합니다.
- 개인 업무공간을 사용합니다. workspace_id로 자료를 구분하지만 팀 초대·역할별 권한·사용자별 확인 상태는 후속 범위입니다.
