# 구현 요구사항

## 목적

실제 기관 공지·페이지 변경을 한 화면에서 확인하고 업체·프로젝트 영향, 확인 여부, 대응 상태와 메모를 관리한다. 한국어 업무용 화면으로 구현한다.

## 출처

/Users/smg/project/noti_search/기관_사이트_및_공지사항_URL.md 파일의 기관과 URL만 초기 목록에 사용한다. 원본 파일은 수정하지 않는다. 실제 수집 연동과 연동 준비를 구분한다.

## 화면

1. 대시보드: 오늘 확인할 업무, 마지막 점검 시각, 신규·변경·미확인·검토 필요 집계, 실패 기관 및 이유, 수동 점검.
2. 월간 캘린더: 점검 예정과 실제 실행 이력을 날짜별 표에 표시. 날짜 선택 시 점검 기관·결과·시각·실패 이유 조회. KST 기준.
3. 기관 관리: 분류·홈페이지·공지 URL, 목록/페이지 비교 방식, 본문 및 제외 영역, 활성화, 최근 성공 시각, 다중 업체·프로젝트 연결.
4. 공지·변경 관리: 원문·게시일·발견 시각, 신규/기준/수정 구분, 전후 내용과 수집 시각, 검색과 필터, 확인·대응·메모·관련 항목 및 이력.
5. 업체·프로젝트: 등록·수정, 소속 업체 및 다중 기관 연결, 관련 공지와 대응 이력.

## 업무 상태

- 확인 여부: 미확인 / 확인 완료.
- 대응 상태: 미분류 / 영향 없음 / 검토 필요 / 대응 중 / 대응 완료.
- 확인 완료와 검토 필요를 동시에 저장할 수 있어야 한다.
- 상태·메모·직접 연결의 변경 시각과 이력을 저장하고 새로고침 후 유지한다.

## 수집 원칙

- 서버에서 실행하며 영구 데이터베이스에 저장한다.
- 첫 수집은 기준 자료로 저장하고 신규 알림을 만들지 않는다.
- 안정적인 공지 키로 중복을 방지한다.
- 직전 성공 수집본과 비교하고 수정 시 별도의 변경 기록을 생성한다.
- 메뉴·시각·방문자 수 등은 선택자로 제외한다.
- 실패와 변경 없음은 구분한다. 실패 시 이전 자료를 보존한다.
- 기관별 오류가 전체 점검을 중단하지 않으며 동일 기관 중복 실행을 막는다.
- 수집 시각·이전 내용·원문 URL을 보존한다.
- 수동 점검부터 구현하고 정기 점검은 비활성 구조로 준비한다.

## 검증 및 전달

실제 기관 2~3곳의 목록·본문 수집부터 화면 표시까지 연결한다. 통제된 자료로 신규·변경·실패·중복 방지·관계 연결·상태 저장·영구 저장을 검증하고 실제 자료와 분리한다.

코드는 GitHub garajilpung/noti 공개 저장소에 올리고 Vercel noti 프로젝트에 배포한다. 환경변수·접속 정보·업무 데이터는 GitHub에 포함하지 않는다. 자체 로그인·권한 관리가 없는 첫 버전은 보호된 미리보기에서 제공한다.
